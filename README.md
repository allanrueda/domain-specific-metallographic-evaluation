# Domain-Specific Multi-Scale Evaluation of Synthetic Metallographic Images

## Overview

This repository provides a Python implementation of a domain-specific, multi-scale evaluation protocol for assessing the quality of synthetic metallographic images generated by Generative Adversarial Networks (GANs).

Conventional evaluation metrics, such as the Fréchet Inception Distance (FID), rely on feature representations extracted from networks pretrained on natural images. However, these representations may not adequately capture the morphological and textural characteristics of metallographic microstructures.

To address this limitation, this work introduces two convolutional autoencoder-based feature extractors trained exclusively on real metallographic images:

- **MaterialAE:** Extracts global feature representations to characterize the spatial organization of metallographic microstructures.
- **PatchAE:** Extracts local feature representations from non-overlapping image patches to characterize local texture patterns.

The proposed protocol evaluates synthetic images using multiple statistical distances in both representation spaces, providing complementary information about global structural similarity and local textural consistency.

The implementation also incorporates uncertainty estimation, real-vs-real calibration, sensitivity analysis, and computational profiling to support a more comprehensive and reproducible assessment of GAN-generated metallographic images.

## Evaluation Framework

The proposed evaluation framework consists of two complementary feature extraction branches.

### 1. Global representation: MaterialAE

MaterialAE is a convolutional autoencoder trained to reconstruct complete metallographic images.

Its encoder maps each input image into a 256-dimensional latent representation:

$
f_g(x) \in \mathbb{R}^{256}
$

These embeddings are used to evaluate the global characteristics and spatial organization of the microstructure.

### 2. Local representation: PatchAE

PatchAE is trained using non-overlapping patches extracted from real metallographic images.

Each image is divided into smaller regions, which are independently encoded into 128-dimensional feature vectors:

$
f_l(p) \in \mathbb{R}^{128}
$

The local representations provide information about texture characteristics and localized microstructural patterns.

The patch configuration depends on the dataset:

| Dataset               | Image resolution | Patch size | Patches per image |
| --------------------- | ---------------- | ---------- | ----------------- |
| Inclusions            | 128 × 128        | 32 × 32    | 16                |
| Corrosion             | 128 × 128        | 32 × 32    | 16                |
| Boriding              | 128 × 128        | 32 × 32    | 16                |
| Hardness indentations | 256 × 256        | 64 × 64    | 16                |

### 3. Evaluation metrics

The implementation calculates the following metrics:

| Metric                  | Description                                                  |
| ----------------------- | ------------------------------------------------------------ |
| FID (Global)            | Fréchet distance between global MaterialAE embeddings.       |
| FID (Local)             | Fréchet distance between local PatchAE embeddings.           |
| Normalized FID (Global) | Global FID normalized by the trace of the real-data covariance matrix. |
| Normalized FID (Local)  | Local FID normalized by the trace of the real-data covariance matrix. |
| MMD² (Global)           | Maximum Mean Discrepancy using an RBF kernel in the global feature space. |
| MMD² (Local)            | Maximum Mean Discrepancy using an RBF kernel in the local feature space. |
| KID (Global)            | Kernel Inception Distance formulation using a polynomial kernel in the global feature space. |
| KID (Local)             | Kernel-based distance using a polynomial kernel in the local feature space. |

The MMD² implementation uses a fixed Gaussian kernel bandwidth estimated exclusively from real embeddings using the median heuristic. Additional bandwidth configurations are evaluated to analyze sensitivity.

The script also computes a global MMD² reference using the bandwidth estimation procedure from the original evaluation implementation.

### 4. Statistical reliability and uncertainty

To characterize the variability of the evaluation results, the implementation incorporates:

- **Multiple random seeds:** Evaluates the effect of independently retraining the autoencoders.
- **Image-level bootstrap:** Estimates sampling variability by resampling original images with replacement.
- **Patch grouping:** Preserves the relationship between patches belonging to the same original image during bootstrap resampling.
- **Real-vs-real calibration:** Estimates a reference variability level by comparing randomly selected subsets of real images.
- **Ranking stability:** Measures how frequently each GAN architecture achieves the best score across different random seeds and bootstrap replicates.

This strategy distinguishes variability associated with autoencoder retraining from variability caused by finite image sampling.

### 5. Computational profiling

For each experimental configuration, the implementation records:

- Training time for MaterialAE and PatchAE.
- Number of trainable parameters in each autoencoder.
- Validation reconstruction loss across training epochs.
- Evaluation time for each GAN architecture.
- Peak GPU memory allocation, when CUDA is available.

## Supported Datasets and GAN Architectures

The implementation supports four metallographic image datasets:

| Dataset identifier | Microstructural domain    |
| ------------------ | ------------------------- |
| `inclusiones`      | Non-metallic inclusions   |
| `corrosion`        | Corrosion microstructures |
| `borurado`         | Borided layers            |
| `dureza`           | Hardness indentations     |

Three GAN architectures are considered:

- Deep Convolutional Generative Adversarial Network (DCGAN).
- Wasserstein Generative Adversarial Network with Gradient Penalty (WGAN-GP).
- StyleGAN2 with Adaptive Discriminator Augmentation (StyleGAN2-ADA).

The script evaluates previously generated synthetic images from these architectures. GAN training and image generation are not included in this repository script.

## Requirements

The implementation requires Python and the following libraries:

- NumPy
- PyTorch
- Torchvision

CUDA is automatically detected when an NVIDIA GPU and a compatible PyTorch installation are available. Otherwise, the evaluation runs on the CPU.

Example installation:

```
pip install numpy torch torchvision
```

For GPU execution, install the appropriate PyTorch version compatible with your CUDA environment. Refer to the official PyTorch installation instructions:

https://pytorch.org/get-started/locally/

## Dataset Organization

The script uses `torchvision.datasets.ImageFolder` to load real and synthetic images.

The expected directory structure is:

```
dataset_root/
│
├── reales/
│   ├── train/
│   │   └── images/
│   │
│   └── val/
│       └── images/
│
├── reales-completas/
│   └── images/
│
├── dcgan/
│   └── fakes/
│       └── images/
│
├── wgan-gp/
│   └── fakes/
│       └── images/
│
└── stylegan2-ada/
    └── fakes/
        └── images/
```

**Important:** Each `ImageFolder` directory must contain at least one class subdirectory. The `images` folders above represent the class directories containing the corresponding image files.

The three real-data partitions have the following purposes:

- `reales/train`: Training data used to train the autoencoders.
- `reales/val`: Validation data used to monitor reconstruction loss.
- `reales-completas`: Complete real-image collection used as the reference distribution for metric computation.

Synthetic images must be organized according to their corresponding GAN architecture.

All images are resized to the resolution specified for each dataset and converted into tensors using Torchvision transformations.

## Running the Evaluation

The script can be executed from a Jupyter Notebook or Google Colab environment using the `%run` command.

### Basic execution

To evaluate the corrosion dataset using the default configuration:

```
%run eval_revision.py --dataset corrosion
```

### Dataset selection

The following identifiers are available:

```
%run eval_revision.py --dataset inclusiones
%run eval_revision.py --dataset corrosion
%run eval_revision.py --dataset borurado
%run eval_revision.py --dataset dureza
```

### Custom bootstrap configuration

The number of bootstrap iterations can be modified using `--boot`:

```
%run eval_revision.py --dataset dureza --boot 200
```

### Custom random seeds

By default, the implementation uses five random seeds:

```
42, 1042, 2042, 3042, 4042
```

These can be modified using `--seeds`:

```
%run eval_revision.py --dataset corrosion --seeds 42,123,456
```

### Custom number of training epochs

The number of autoencoder training epochs can be specified using `--epochs`:

```
%run eval_revision.py --dataset inclusiones --epochs 20
```

### Custom dataset root

The default dataset root is `/content`.

To specify another directory:

```
%run eval_revision.py --dataset corrosion --root /path/to/dataset_root
```

### Patch extraction configuration

Two patch extraction modes are available:

```
%run eval_revision.py --dataset corrosion --patch_mode fixed
```

The `fixed` mode uses the corrected patch extraction procedure, preserving the correspondence between image channels and spatial patch positions.

The `original` mode reproduces the patch extraction operation used in the original experimental notebooks:

```
%run eval_revision.py --dataset corrosion --patch_mode original
```

This option is provided for experimental compatibility and comparison with previous results.

## Output Files

For each execution, two files are generated in the current working directory.

### 1. JSON results

```
resultados_<dataset>_<mode>.json
```

This file contains the complete experimental results, including:

- Dataset configuration.
- Random seeds.
- Hardware information.
- Autoencoder training times.
- Training and validation loss histories.
- Model parameter counts.
- Real-data covariance traces.
- Fixed Gaussian kernel bandwidths.
- Real-vs-real calibration results.
- Evaluation metrics for each GAN architecture.
- Bootstrap distributions.
- Evaluation times.
- Peak GPU memory allocation, when applicable.

### 2. Text summary

```
resumen_<dataset>_<mode>.txt
```

This file provides a compact summary of the experimental results, including:

- Mean metric values across random seeds.
- Standard deviation associated with autoencoder retraining.
- Bootstrap standard deviation.
- Bootstrap bias estimates.
- Real-vs-real reference values.
- GAN ranking stability.
- Computational cost.

These outputs can be used for subsequent statistical analysis, comparison of GAN architectures, and preparation of scientific tables and figures.
